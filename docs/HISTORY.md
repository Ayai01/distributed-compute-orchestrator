# DCO 版本日志

## 1.0.43 · 2026-11-21

- 排队排序、适配、扩核配额和面板聚合使用锁外快照。实时账本只核对当前任务及实际资源，再提交一笔预留。
- 同摘要传输只在登记时加锁，网络读写、缓存可见性与提交节拍全部在锁外等待。重复 worker 采样跳过中心写入。
- 准入公开返回 `dispatch_paused`，便于工程识别停派窗口。

## 1.0.42 · 2026-11-21

- 探针超时显示为重连。自动失联路由保留原任务和身份，退避最长五分钟后继续探测。
- 同一轮扩核计算复用固定宽度队列和占用统计。已用满原授权的阶段保持当前授权，减少并发下的调度锁争用。

## 1.0.41 · 2026-11-21

- 连接池和传输节拍在锁外检查取消，节点探测在锁外等回包。健康采样离开调度锁后读取传输统计。
- 中转可关闭软件字节限速，短派发和结果领取使用空余连接。共享资产从 1 MiB 起支持断点续传。

## 1.0.40 · 2026-11-21

- worker 按实际内存和提交空间为启动留额。已获足额内存的任务可在冷探针校准期间开算，校准与启动节拍的等待释放进程创建锁。
- 更新内存准入、租约认证与能力显示回归使用的测试配置。

## 1.0.39 · 2026-11-21

- 新增可执行 RAM 暂存的准入和启动空间核验。暂存失效且尚未启动的任务按原 ID 保留回执和费用。
- Windows 文本模式关闭已附加控制台时正常退出，保留无控制台启动。

## 1.0.38 · 2026-11-21

- 多核精确阶段取得足额授权后，由 worker 在本地核对启动凭据，避免再经中心往返确认。
- 精确阶段分列等授权和等启动确认的墙钟，启动到期标明所处阶段。

## 1.0.37 · 2026-11-20

- 租约回信重发复用上一次确认，首次启动遇到过期授权时按零活跃重新协商。
- 工具表路径以 worker 发布为准。首步与后续步骤读取同一绑定。
- 原件回执记录接收至开算、资源等待和原生执行墙钟，CPU 账继续按进程树实测。

## 1.0.36 · 2026-11-20

- 原生进程启动前写好只读用的工具表，任务通过 `REMOTE_COMPUTE_TOOLS_FILE` 读取。
- `min_start_cpus` 声明首次启动的核数下限，满足能力和资源的 worker 获得该原单，排队独立计时。后续阶段继续弹性授权。
- `admission(activity=True)` 给出项目活跃核数的观测下界与覆盖率，保留逐单未知值。

## 1.0.35 · 2026-11-20

- 历史终态只在缓存有效期内保护输入。超龄输入具备活跃引用时继续保留，原请求、结果和费用按各自生命周期管理。
- 解包缓存后台校准实际体积，包含任务生成的构建文件。启动读尺寸索引并把缓存回收交给后台。

## 1.0.34 · 2026-11-20

- 支持按摘要复用构建制品与检查点，由中心优先分配已有热缓存的兼容 worker。
- 固定单核短任务可使用快速启动。执行回执支持进程树分阶段 CPU，超时前可提交经过摘要验证的检查点。

## 1.0.33 · 2026-11-20

- 终端进度只显示已知百分比，未知留空。CPU／上限列占 7 个显示列，窄模式将空间留给任务标签。

## 1.0.32 · 2026-11-20

- worker 已失联且任务尚未提交时，释放预留资源并用原 ID 重新排队。提交状态不确定时继续在原 worker 核对。

## 1.0.31 · 2026-11-20

- 不同 worker 对共享缓存的命中检查可并行，同一 worker 合并重复检查。缺失资产仍按共享卷和内容摘要只上传一次。

## 1.0.30 · 2026-11-19

- Windows 启动复用已标记的较大共享 RAM 盘，重载跟随当前发布入口，避免更新批处理时旧窗口从错误的位置继续执行。

## 1.0.29 · 2026-11-19

- 已获 1 核的固定单核阶段在临时超配上限回落时沿用该核，真实内存限额继续参与准入。

## 1.0.28 · 2026-11-19

- 共享资产上传中断时切换到同卷接收端，查询持久化进度后继续。已确认前缀不会重传，任务仍按原 ID 领取和计费。

## 1.0.27 · 2026-11-19

- 学校共享缓存的大资产按 2 MiB 分块确认。断线后从接收端的持久偏移继续，完整校验后发布同一 SHA256 制品。
- 同一共享缓存的兼容接收端可为旧 worker 接收大资产。原任务 ID、结果和费用按原合同结算，回执记录选中的资产、确认字节及恢复偏移。

## 1.0.26 · 2026-11-19

- 调度选定 worker 后，仅派发已登记的匹配架构依赖。大资产上传回执丢失时先查缓存，再决定是否重传。
- 面板将 `rtl` 能力统一显示为 Chisel。原 ID 和冻结请求继续按原格式结算。

## 1.0.25 · 2026-11-19

- 显式使用 ONNX INT8 的任务将同一次执行的 ONNX 绑定统一到已探测的 INT8 环境。
- 旧 RTL 编译缓存提示归并至完整 RTL/Chisel 包，缓存由 worker 按实际工具状态使用。

## 1.0.24 · 2026-11-19

- RTL/Chisel 作业默认绑定已选 worker 注册的 firtool。用户提交的显式编译环境沿原任务保留。

## 1.0.23 · 2026-11-19

- 默认环境称为 `python`。独立显示 `ng47`、`hsp` 和 `onnx`，RTL 总览标明 Chisel。
- 用实际 Chisel/RTL 工具探测决定准入。暂停接单、滚动版本和单核交接优化各自按实际状态处理。

## 1.0.22 · 2026-11-19

- 普通任务按一个固定能力包准入和派发，默认 `cpu`。工具、ABI、共享路径和原生缓存信息归运维端。
- 公开接口与终端能力列使用同一目录。旧调用映射至等价包，已受理原任务继续按原请求结清。

## 1.0.21 · 2026-11-19

- 公布 `single-core-phase-handoff`，由执行端协议确认。中心兼容已具备同等交接的 1.0.20 worker。
- 收件遇本地连接池繁忙时在原读取期限内重试，不产生新的原任务。

## 1.0.20 · 2026-11-19

- 批量简版状态直接读取原任务快照。SDK 遇到短时状态连接故障时保留已受理原 ID 并继续收件。
- 同一单核原任务在同步计算阶段之间沿用已确认的核；精确阶段一次确认新资源后启动。多核任务仍按需求归还资源。
- 终端进度有总量时显示百分比，否则显示已上报的阶段。

## 1.0.19 · 2026-11-19

- 公开健康、能力和准入读取现有快照。资产检查与准入登记使用已有的短时缓存保护，取消资产保留无需调度锁和单独的交接锁。

## 1.0.18 · 2026-11-19

- 默认 Python 部署固定 PyTorch 2.14.1，验收实际解释器、构建和张量运算。CPU 与 CUDA 13.0 使用各自的官方构建。
- 公开的容量与任务活动查询直接读取现有采样，避免等待派发和弹性调度锁。
- 取消原任务资产保留时立即回执，上传后的缓存整理交给后台维护。

## 1.0.17 · 2026-11-19

- 同阶段归还 CPU 时可保留已授权内存。SDK 继续重试未获确认的资源归还。
- 容器 CPU 百分比按其实际 CPU 配额采样，面板明确区分预留线程与使用率。

## 1.0.16 · 2026-11-19

- 中转上传和下载独立计速，增加普通大包并发，短派发、结果和控制保留各自连接。
- 资产缓存运行中按七天未命中和 64 GiB 总容量回收。校内共享副本损坏或缺失时由原输入恢复。
- 面板忙时继续显示最近快照并排队更新，避免弹性调度繁忙时读到长期过期的状态。

## 1.0.15 · 2026-11-19

- 增加 `elf-aapcs64` 原生载体准入，支持学校 ARM64 复用经等价验收的可执行件。

## 1.0.14 · 2026-11-19

## 1.0.13 · 2026-11-19

- 全量任务目录和原 ID 前缀搜索只向运维开放。工程通过已知原 ID 批量查询和领取结果。

## 1.0.12 · 2026-11-19

## 1.0.11 · 2026-11-19

## 1.0.10 · 2026-11-19

- 按原 ID 原子登记运输副本退休。后台回收，重复或缺失 ID 幂等成功。
