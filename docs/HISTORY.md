# DCO 版本日志

## 1.0.62 · 2026-11-25

- 自动重连使用与状态目录同寿命的 worker 身份。容器 MAC 探测值变化后，原 worker 仍可回连；脱离状态和期望身份一起持久化。
- Worker 返回某笔原单不存在时，中心核对该原单的恢复策略，节点在线状态继续由心跳判定。

## 1.0.61 · 2026-11-25

- 中转连接池只唤醒当前可用通道中最早等待的请求。保留既有并发预算和心跳、控制、结果上传下载通道。
- Worker 在已认证的任务请求开始接收时登记原 ID。接收或解包期间收到取消就按原 ID 写取消回执，跳过进程启动。
- Range 回传直接使用原归档缓冲区的续传区段，保持内容、ETag 和 HTTP 范围语义。

## 1.0.60 · 2026-11-25

- Worker 批量取消先向全部目标进程发出终止信号，再保存逐单回执。原任务的取消控制优先于中转状态采样和扩容请求。
- 派发与状态读取遇到中转 429、502、503、504 时沿原节点、原 ID 核对，保留已经发出的资源授权。健康状态先发布，再做独立 TCP 测量。

## 1.0.59 · 2026-11-24

- 新任务统一从 1 核启动。SDK 和中心拒绝显式 `min_start_cpus`，支持通过 `max_cpus` 声明运行期扩容上限。已登记的原单保留冻结请求、原 ID 和回执。

## 1.0.58 · 2026-11-23

- 中心支持把设备的可调度 CPU 核数设为 0，保持监控并让已运行的原任务自然完成。`cpus 设备 auto` 恢复自动预算。

## 1.0.57 · 2026-11-22

- 运维原单支持经授权的设备名单。中心在名单内调度，保留原请求和授权理由。
- 普通任务继续使用固定能力包。制品摘要只校验内容和兼容性，热缓存由 DCO 管理。

## 1.0.56 · 2026-11-22

- 中心将批量取消按调用时的原 ID 持久化，按 worker 合并一轮控制请求。取消过程保留原账本、已交付结果和费用。
- 学校链路使用独立心跳连接，单节点限制未确认派发。过载队列返回可重试的 429，SDK 按实际提交窗口节流。
- 按原节点核对断线任务终态和费用。沿用 1.0.53–1.0.55 的状态采样、续传及已归档输出读取修复。

## 1.0.55 · 2026-11-22

- 已封存的成功原单直接提供归档快照，避免等待同一任务上一次回传持有的锁。

## 1.0.54 · 2026-11-22

- 公开单文件领取优先返回中心已封存的原任务产物。学校大资产上传按确认延迟调整块大小，从接收方已确认的位置续传。

## 1.0.53 · 2026-11-22

- 学校中转读取发生故障时，同节点的已接任务共享健康采样恢复，避免每个原单同时新建连接。

## 1.0.52 · 2026-11-22

- Worker 按原 ID 并行接单，解包期间只保护本单资产。公开状态区分资产准备、派发交接和执行，回执记录 POST 连接等待、发送和回包耗时。准备阶段可轮询，进度列仅显示有依据的百分比。

## 1.0.51 · 2026-11-22

- 深队列优先消耗未提出请求的弹性扩容预留，已获核心和待处理扩容请求保持原有保护。
- 中心、本机和 20 台远程 worker 滚动升级完成，任务状态目录、能力包和传输协议保持兼容。

## 1.0.50 · 2026-11-21

- 续租按当前节点核对排队任务的核心留量，密集共享队列跳过重复分配，保持逐格分配结果一致。
- 面板从已发布状态读取任务和节点，刷新期间继续返回上一帧，避免采样持有调度锁。
- 中心、本机和 20 台远程 worker 已统一上线，五工程公开 SDK 和学校 ARM64 传输完成定向验收。

## 1.0.48 · 2026-11-21

- 终端在 80 列起显示百分比。业务阶段上报总量时优先显示业务进度，缺少分母时采用 worker 已完成的命令步数。网页沿用同一口径。

## 1.0.47 · 2026-11-21

- 学校共享盘从 64 KiB 起按原 ZIP 偏移续传，协商压缩并记录实际发送的请求体字节。跨节点复用已确认的副本。
- 缓存解包计量移出共享锁，合并退休后的清扫。远端回收按原节点身份办理，缺少路由时保留凭据、等待重新接入。
- SDK 支持直接预置已打包的 ZIP 和设置本机领取线程数。

## 1.0.46 · 2026-11-21

- 拒绝会缩窄公开能力池的普通原生制品和检查点引用。已受理任务沿原 ID 运行和收件。
- 短阶段和宽阶段同时申请核心时采用同一任务权重比例。

## 1.0.45 · 2026-11-21

- `priority` 默认 1，作为同一工程内的弹性核心配额权重。旧请求中的非正优先级按 1 调度，保留原 ID 和请求字节。

## 1.0.44 · 2026-11-21

- 终端、看板快照和能力目录只展示专项能力。Python 为基础环境，默认提交和准入计数保留兼容。
- 任务列表显示生效的 `priority`。废止单核亲和权重，兼容已提交的原请求和旧 SDK 调用。

## 1.0.43 · 2026-11-21

- 在锁外排队、匹配、计算扩核配额和聚合面板数据，落位前在实时账本逐笔校验资源。
- 资产传输、提交节拍和重复状态采样减轻锁竞争。自动失联重连进入有界退避，保留原任务。
- 公开准入增加 `dispatch_paused`。中心和 worker 从 1.0.41 直接切换，1.0.42 为内部候选。

## 1.0.41 · 2026-11-21

- 连接池与传输节拍在锁外检查取消，节点探测在锁外等回包。健康采样离开调度锁后读取传输统计。
- 中转可关闭软件字节限速，短派发和结果领取使用空余连接。共享资产从 1 MiB 起支持断点续传。

## 1.0.40 · 2026-11-21

- worker 按实际 RAM 和提交空间为启动留额，已获足额内存的任务可在冷探针校准期间开算。校准和启动节拍的等待释放进程创建锁。
- 更新内存准入、租约认证与能力显示回归的测试配置。

## 1.0.39 · 2026-11-21

- 可执行 RAM 暂存支持资源申报和开算前核验，暂存失效前的尝试沿原任务回执结算。
- Windows 文本模式收到已附加控制台关闭事件时正常退出，兼容无控制台启动。

## 1.0.38 · 2026-11-21

- 多核精确阶段获得足额授权后由 worker 本地确认启动，分别记录等授权和等启动确认的墙钟。

## 1.0.37 · 2026-11-20

## 1.0.36 · 2026-11-20

## 1.0.35 · 2026-11-20
