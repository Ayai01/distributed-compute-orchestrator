# DCO 重要变化

## 2026-10-21 运行环境能力收束

工程与算法的重复 Python 名称归并为 `python_numpy/python_scientific/python_torch_pyg`；独立 ONNX、布局和原生工具按实际依赖保留。修复工具模板匹配仍按原始键名、以及缓存同步仍按工程标签筛选消费者的缺口，能力汇总与 SDK 使用同一规范名称。旧请求、模板、实际回执与在途绑定保持；新绑定先在线登记，忙碌服务留到空闲重载。

## 2026-10-21 语义能力与紧凑表头

能力注册、任务及准入拒绝引擎哈希和平台选择标签；worker不再发布OS能力。引擎不生成或保存哈希，数值兼容性回归执行/测量协议与容差。旧错误约定同步撤回，三个设备配置清理后重启验收。表头统一短标识，覆盖38–200列完整性与既有着色、分页。

科研缓存同步跟进生产者语义格式：AOP以明文执行环境交换原始角点，接收端使用自己的UUID目录；RGCN共享布局记录以完整逻辑观测交换，未知协议旧UUID观测保留同步并退出测量命中。保持原锁、科学分区和增量批次，重复同步零记录导出。

修复语义工具名已准入却在执行模板中按旧配置键查找的缺口。命令首项和路径/环境变量统一解析语义别名，保留多参数前缀及已有工具绑定，合法含加号/点的工具名可正常执行；三设备在线补齐ng47绑定，已有任务保持。

## 2026-10-20 表头与任务标签

固定资源列使用完整短表头，避免中文标题被中间省略。Bench 父任务显示场景编号和单项预算，ARH 门禁显示短描述；原标签、请求和完整明细保持。

## 2026-10-20 满载后的阶段增长

派发时为已确认但未满足的自动阶段增长需求保留公平份额内的新空核，避免重复借出导致下一安全边界仍拿不到额度。保护沿用原内存模型、优先级及同工程分配，需求降低或任务退出即释放；原任务通过后续 `resize` 领取，不热改运行中的池。

## 2026-10-20 RAM 实际用量与阶段公平

RAM 准入区分申报量和已采样进程树 RSS，归还高估的空预留；默认预算和实时系统余量分别配置。自动任务在安全阶段边界为同工程就绪任务腾出线程，排队按优先级及当前线程/份额补足；看板显示份额与优先级。Windows 端口所有者和停止进程改用原生 API，移除残留 WMI 启动阻塞。ku26s 补齐 ARH 固定 INT8 推理能力并验证 Linux 原生构建传输。

修复最近通知中纯数字四位短 ID 被误着黄色；方括号 ID 与任务表 ID 统一使用青色。

自动任务的有限阶段并行需求也参与同工程公平分配，重复当前授予会重新核对就绪任务；工程按实际工作量申报，无须把正整数需求改成整节点请求。

中心在接受任务前检查引用资产是否已同步，避免静态缓存 ID 缺失到派发时才中断；补齐资产后保留同 ID 提交语义。

启动先加载已就绪设备，慢节点后台继续探测；单设备控制不再等待其它离线设备刷新。

Linux 新进程尚未出现于缓存进程扫描时继续保留启动 RAM 预留；测试服务配置与真实设备配置隔离，终端键盘夹具在 Windows/Linux 共用。

## 2026-10-20 启动与防休眠

## 2026-10-20 文档与手动缓存同步

## 已完成的架构收敛

统一名称为 Distributed Compute Orchestrator，保留 remote_compute 包和 REMOTE_COMPUTE_* 协议兼容。对外端口统一 26133，hybrid 本机 worker 改为中心进程内调用；设备选择收敛到操作端和中心，科研工程使用汇总能力。

状态、输入和未领取成果从临时盘职责中分离，持久保存在普通磁盘；可重建临时物复用每设备唯一 8 GiB RAM 盘。网络恢复沿用原任务 ID，结果取回使用独立连接及续传。远端 CPU/RAM 协商改为 worker 本地 lease 和中心已有连接，旧反向回调与专项 live_patch 入口退役。

系统 Python 3.14 成为日常维护环境，setup 复用系统解释器；源码保留 3.7–3.15 兼容。所有常驻入口统一可见终端检查，重载保留原终端和任务状态。Windows 服务生命周期内的防自动休眠请求随退出释放。
