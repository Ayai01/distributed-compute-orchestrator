更新：2026-10-28（HST）。本机及四个工作节点运行0.8.43，DCO源码新增启动历史索引与分页 brief 兼容修复，提交为`cddb4bd`，CLI有界任务表补丁为`0d2d13c`。算力校准仅手动触发，启动、重连和资源变化均不自动校准。运行入口见[README](../README.md)，协议见[DESIGN](DESIGN.md)，旧版本记录见[HISTORY](HISTORY.md)。

## 本轮修复

- 提交回应丢失时，SDK按原任务ID及完整请求摘要核对受理状态；仅确认未受理后重发相同请求，避免成功任务因控制面短暂断连而重复执行。
- 批量状态查询逐项处理终态回执被并发领取、删除的情况。新SDK同时兼容尚未重载的中心：遇到该清理竞态时有界重读原批次，任务身份和实际终态保持。
- 低核启动且上限更大的任务优先分散到空闲兼容设备，有限阶段请求参与同工程协作借还；归还至1核后可重新借核。重连和重试保留原请求类型，固定整组仍取得完整宽度。
- `max_cpus`只设上限。正整数启动任务在首次扩核请求前按实际初始宽度计入需求，避免尚在准备的任务让计算任务过早退核。
- Bench在主线程初始化内存采样后端，再启动采样线程，消除Linux首次加载psutil与threadpoolctl之间的锁等待；科学算法及输入保持原身份。
- `start_paused`在中心调度线程创建前生效，原ID仍可查询和领取。本机已配置暂停启动；运行期恢复不改下一次启动策略。
- 终态任务删除后，晚到状态和重试不再重新创建目录。已发布成果先核验，再清原ID和一次性副本。
- Windows工作目录仅设置低完整性标签，保留DACL继承；worker与RTL共用同一实现。
- 工作粒度由调用工程按实测和完整状态边界确定。30分钟用于复查长段，科学预算、工作目标和故障超时分别记录；DCO负责能力、资源、任务与传输。
- 看板任务翻页改为 PgUp/PgDn，旧 Ctrl+Tab/空输入 Shift+Tab 翻页路径已删除；命令输出保留在 Ctrl+PgUp/Ctrl+PgDn。任务状态沿用已有命令步记录生成进度比例，宽看板显示 Prog 列，窄看板压缩到 Tag 前缀，不增加采样、网络请求或磁盘扫描。
- 长历史任务表增加有界页接口 `Client.status_page(limit, offset)` 与 `GET /jobs?limit=&offset=`；CLI `jobs` 只读取最近页，完整 ID、批量状态和磁盘回执保持不变。旧无参 `/jobs` 为兼容保留，但不再用于高频巡检；索引启动加载已在本机常驻服务生效。分页 brief 兼容层同时保留 `items/total/offset/limit/has_more`，不再把分页字段当成任务行。
- 启动卡死根因已闭合：调度器原先在启动时逐个打开约19万份终态 `result.json`，并把本机约2.2万份 worker 回执一并驻留内存。现在每个状态根维护紧凑的 `history.index.jsonl`，启动只加载终态身份/资产引用和非终态 ID；完整回执仍按原 ID 冷读。重建索引统计调度器190,823条、本机worker21,665条，当前无非终态残留扫描；服务从可见窗口启动后约247MiB RSS，健康检查与分页 brief 实测通过。旧迁移索引的历史顺序只影响任务表展示，空闲边界再重排，不影响原ID读取或科研任务执行。
