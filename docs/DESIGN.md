# DCO 设计合同

## 部署

中心管理原任务 ID、准入、调度和结果索引。Worker 执行、采样和结算资源。看板与网页使用运维接口，读取同一份状态。无图形界面的服务用 `--no-dashboard` 输出纯文本。

## 连接与身份

可达设备使用直连。需要转发的设备经认证中转接入，中心沿稳定身份维护路由。节点接口地址与中转入口仅向运维人员显示。断线重连先按原 ID 查已受理状态，保留已付工作和已接收结果。

## 能力与资源准入

普通 SDK 以 `requires`、CPU、内存和加速器语义提交，由中心匹配实时就绪资源。固定宽度任务整组获配。弹性任务根据就绪宽度借用或归还资源。GPU、NPU 和 CPU 按实际后端就绪能力上报。

`admission(project, activity=True)` 返回公开的聚合容量、能力可用量、提交窗口和所请求工程的在途任务。CPU 能处理多少和眼下还能分配多少分别记录。调用方用 `statuses(ids)` 短请求批量查询，用原 ID 领取结果。节点名、设备 IP、中转地址和部署分组归运维端。

## 传输与生命周期

内容摘要标识输入，先用 `sync_files` 发布一次，后续任务只引用摘要。共享缓存对同一内容合并传输，并在使用期间保留引用。常规作业通过 `outputs` 只声明需回传的 KiB 级摘要。大型检查点用缓存引用保留在算力端，再按需领取。

结果领取与资产上传使用独立连接池。大包按共享预算分块，短任务派发、状态查询和小结果保持可用。结果按原 ID 校验并持久化，费用入账后释放运输副本。
