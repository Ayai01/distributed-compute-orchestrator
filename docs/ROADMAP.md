# DCO 后续工作

## 持续职责

- 维护一个当前调度和SDK合同，按实际调用者完成中心、worker及工程适配；部署统一版本，核对实际授权、执行线程与CPU时间。
- 检查工程的真实就绪供给和资源需求；就绪输入充足时保持排队，尾项及时归还闲置核心，完成即领取与补位。
- 新工具和加速器先用真实最小任务验收能力；科学质量、执行/测量协议和数值容差由调用工程维护。
- 传输按不可变内容复用，科研结果先由工程持久发布，DCO保留原ID索引、费用和恢复通路，再回收已消费副本。
- Linux临时目录复用已有用户运行时目录；显式磁盘TMP的切换在所属worker排空后进行，持久状态留普通磁盘。

## 验收要求

调度变化检查四核优先、单核准入、空闲扩核、跨工程份额、长尾收缩、内存限制和断连后的原ID连续性。执行器借还检查实际进程/线程与授权一致，并核对科学输入和结果。CLI及文档核对真实参数与入口。原生后端变化使用相应原生检查。

当前维护、运行版本及已完成验证见[STATUS](STATUS.md)。后续工作以真实故障、调用需求或用户明确目标受理。
