# DCO 后续方向

## 持续维护

长科研任务由原Owner接入完整状态分段、发起端紧凑缓存及结果消费后释放。工作段按实测规划，30分钟用于复查粒度而非强制截断，保留现有就绪供给和原科研预算；DCO复用原子文件、版本领取及结果发布合同。先验连续与分段的下一候选/状态/NFE/费用一致，再在安全边界迁移，不为传输另开全量实验。

1. 先修实际调用发现的 CLI、权限、准入、借还和结果领取问题；沿现有中心/worker/SDK 边界处理，调用工程继续持有科研语义。
2. 新工具或加速器按真实最小任务验证能力再登记；更新现有部署先核对任务和状态根，空闲重载后检查实际运行版本。
3. 传输优化围绕内容资产复用、有限 pending 和原 ID 恢复，记录吞吐、等待、资源及结果身份；不改变研究批次和代际边界。

## 已登记待验证

统一SDK准备窗口与已知ID批状态由DCO维护，Bench、RGCN、ARH原负责人在自己的控制器接入，保持冻结worker及科学输入；同项目共用pending计数，先持久发布子结果再归还CPU和删除原回执。AOP当前有界角点合批及动态窗口继续兼容，以接入和远程交互演示文档完善为主。各项目记录旧中心兼容、实际请求数及费用连续性后，再在安全空闲边界加载服务端批查询，不重跑既有性能评分。

任务终态期间的迟到lease回执修复已通过隔离验收；在现有科研批次自然空闲时加载，保留原输入、回执和成本。

ku26s现有任务TMP继续使用普通磁盘；排空且具备挂载权限后，验收16GiB独立tmpfs与共享盘锁、状态盘隔离和退出回收。

ARH生产INT24及保护/故障路径、PC/TX真实CUDA与PyG验证已完成。RGCN已通过CPU保存门槛及相同数据/起点/两轮预算的同机CPU/CUDA比较，完整计算实测1.77倍；后续训练按科研质量门槛明确选择后端，已有CPU实验保持。Arc/XPU在有实际后端收益时接入。SPICE、RTL和小批FIBER搜索继续CPU，硬件、驱动、数值及加载事实登记到STATUS和现有维护状态。

## 改动验收

CLI/文档核对参数、示例与返回码；调度或权限变化使用对应隔离单测；SPICE/RTL执行链变化运行所需原生检查。复用仍适用的历史证据，明确写入本轮实际验证范围。服务有在途工作时保留运行实例，源码验证与空闲部署分别完成。
