# DCO 后续方向

## 持续维护

1. 先修实际调用发现的 CLI、权限、准入、借还和结果领取问题；沿现有中心/worker/SDK 边界处理，调用工程继续持有科研语义。
2. 新工具或加速器按真实最小任务验证能力再登记；更新现有部署先核对任务和状态根，空闲重载后检查实际运行版本。
3. 传输优化围绕内容资产复用、有限 pending 和原 ID 恢复，记录吞吐、等待、资源及结果身份；不改变研究批次和代际边界。

## 已登记待验证

任务终态期间的迟到lease回执修复已通过隔离验收；在现有科研批次自然空闲时加载，保留原输入、回执和成本。

ku26s现有任务TMP继续使用普通磁盘；排空且具备挂载权限后，验收16GiB独立tmpfs与共享盘锁、状态盘隔离和退出回收。

ARH生产INT24及保护/故障路径、PC/TX真实CUDA与PyG验证已完成。RGCN已完成CPU保存门槛及相同数据/起点/两轮预算的GPU诊断，继续用同机CPU对照核实完整收益，由科研负责人按质量门槛决定采用。Arc/XPU在有实际后端收益时接入。SPICE、RTL和小批FIBER搜索继续CPU，硬件、驱动、数值及加载事实登记到STATUS和现有维护状态。

## 改动验收

CLI/文档核对参数、示例与返回码；调度或权限变化使用对应隔离单测；SPICE/RTL执行链变化运行所需原生检查。复用仍适用的历史证据，明确写入本轮实际验证范围。服务有在途工作时保留运行实例，源码验证与空闲部署分别完成。
